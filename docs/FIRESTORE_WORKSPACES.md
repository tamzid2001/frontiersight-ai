# Clerk and Firestore scene persistence

Set `AUTH_PROVIDER=clerk` after configuring the server-only fields in `.env.example`. The existing `/api/scenes`, `/api/scenes/update`, `/api/scenes/delete`, `/api/me` and `/api/org` endpoints then use verified Clerk identity and durable Firestore scene storage. Missing configuration fails closed; no scene is silently saved into Vercel's ephemeral SQLite filesystem. Local legacy mode remains available when the feature flag is absent.

The browser loads the pinned Clerk JS 6.42.0 SDK through the configured issuer. Its session tokens are never written into localStorage. User/organization changes select a new namespace; personal Pro does not grant a free organization a paid entitlement. Organization settings use Clerk's own controls. Keep membership optional and preserve the included 20-member configuration. No paid Clerk add-on has been purchased.

Data path: `quantura_web/frontiersight-ai/tenants/{user_USER_ID|org_ORG_ID}/records/{uuid}`. Scene payloads are capped at 256 KiB. GET returns at most ten full scenes per page; follow `next` using `after`. Write requests require a 16–128 character `Idempotency-Key`. Updates and deletes require `expectedVersion`. Only organization admins may delete shared records. All record/counter/audit/receipt changes transact together; no model or billing calls run in retried callbacks. Minute request counters cap per-tenant requests. The browser must not treat a failed update as a successful new create.

This integration does not automatically migrate legacy SQLite scenes/accounts to Clerk, and intentionally disables legacy SQL-backed billing, BYOK, support-ticket and lead-capture mutations in Clerk mode. They return a configuration error rather than pretending to persist. Configure billing through Clerk, or complete a separately reviewed Stripe migration. Existing public deterministic physics/MCP tools are not converted into private workspace tools by this storage change. Advanced metered analysis and third-party API usage still require separate production enforcement review.

See `packages/enterprise-web/README.md` for server IAM/rules responsibilities, TTL/index candidates, cost bounds, HMAC/rollback limitations, account-erasure limitations and provider prerequisites. Production Firestore metadata confirmed an existing Native-mode default database in `quantura-e2e3d`; published rules could not be read by the current session. No production rules, IAM, database, data, prices or deployments were changed. Before activation, review the published rules for broad allows and grant an appropriately scoped service identity. Do not copy a developer's broad OAuth credentials to Vercel.

Validation is against an isolated `demo-quantura-web` emulator with direct client access denied. Real signed sessions are verified by the official Clerk SDK. `scripts/verify-firestore-emulator.sh` runs both language suites; their coverage artifacts are distinct. React/vanilla-browser execution is not included in the server coverage percentage. Real production payment, account lifecycle and cloud load verification remain required.

Latest local evidence: 86 tests passed, including 10 new Firestore/authentication/HTTP tests. New Python modules: 98.37% line coverage, 96.77% branch coverage; see committed `coverage/firestore.xml`. The server coverage excludes vanilla browser execution.
