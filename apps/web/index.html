How it works

⌖

1 · Observe

SAM 3.1 segments and tracks people, forklifts, robots in video. Muse Spark proposes what to look for — it never invents a detection.

✓

2 · Verify

Closest-approach, time-to-collision, continuity and constraint checks run in a seeded, reproducible engine. Uncalibrated video stays in pixel space — no fake metres.

⇄

3 · Counterfact

“What if the forklift had slowed 1s earlier?” A deterministic braking simulation reruns the world, Monte-Carlo intervals included, and an independent verifier checks the result.

    Create Lab — build a scene, set the paths, run the proof

    Create components, give each one a path and a speed, watch them move, then run the same deterministic analysis and counterfactual pipeline used for the built-in scenarios. The stage is a 16 × 14 metre floor plan; positions are metres, so metric claims are valid by construction. Nothing here is pre-baked: tracks are sampled from your paths at 10 Hz when you press Run analysis.

    How it flows

    Run analysis samples every path into timestamped tracks, runs all-pairs closest-approach/TTC analysis, proposes a braking counterfactual for the focus pair, and lands you in the Studio with the full agent trace. Pick the counterfactual agent in the Counterfactual screen — it defaults to the first moving component.

    Counterfactual simulator

    Pick the scene, the agent that intervenes, and who it must avoid. Change anything — scene, agent, target, timing, braking — and the deterministic simulation reruns on the server. The map shows where bodies actually go; the chart shows how close they get.
